# docs-command

기능 코드를 분석해서 `docs/` 경로에 상세 기능 명세 MD 파일을 자동 생성하고, 작성 후 코드와 다시 대조 검증까지 하는 Claude Code 플러그인입니다.

## 만든 이유

기능 구현 후 문서화를 별도로 작성하는 건 번거롭고, 구현과 문서가 어긋나는 경우가 자주 생깁니다. `docs-command`는 실제 코드를 직접 읽어 분석하기 때문에 추측 없이 구현 기반의 명세를 작성합니다. 파일 경로나 키워드를 주면 연관 파일까지 탐색하고, 아무것도 안 주면 최근 커밋 diff를 기준으로 자동 분석합니다. 문서를 다 쓴 뒤에는 방금 쓴 내용을 소스 파일과 다시 대조해서, 불일치가 있으면 바로 고치고 무엇을 고쳤는지 보고합니다.

## 설치

```
/plugin marketplace add jun0x2dev/jun0x2dev-plugins
/plugin install docs-command
```

## 명령어

| 명령어 | 설명 |
|--------|------|
| `/docs-command:docs-command` | 기능 명세 문서 생성 |
| `/docs-command:docs-command src/controller/UserController.java` | 특정 파일 기준으로 문서 생성 |
| `/docs-command:docs-command payment` | 키워드 기준으로 관련 파일 탐색 후 문서 생성 |

## 동작 방식

1. 인자가 있으면 파일 경로 또는 키워드로 관련 파일 탐색
2. 인자가 없으면 `git diff HEAD~1 HEAD`로 최근 변경사항 분석
3. 관련 파일(Controller/Service/DAO/Mapper 등)을 직접 읽어 구현 내용 파악
4. 목적에 맞는 템플릿(사양서형 / 변경이력형)을 골라 도메인별 하위 폴더(`docs/auth/`, `docs/payment/` 등)에 명세 MD 파일 생성
5. **작성한 문서를 소스 파일과 다시 대조 검증** — 불일치를 찾으면 즉시 수정하고 결과 요약 보고
6. 커밋 여부는 사용자가 직접 결정

## 생성 문서 구조

기능의 성격에 따라 두 템플릿 중 하나를 쓴다.

### 사양서형 (신규/기존 기능을 처음부터 정리할 때)

| 섹션 | 포함 조건 |
|------|-----------|
| `## 개요` (요약 포함) | 항상 포함 |
| `## 관련 파일` | 항상 포함 |
| `## 엔드포인트` | REST API가 있는 경우 |
| `## 응답 구조` | JSON 응답이 있는 경우 |
| `## 처리 흐름` | 복잡한 처리 단계가 있는 경우 |
| `## 사용 테이블` | DB 테이블을 쓰는 경우 (인덱스 현황 포함 가능) |
| `## 핵심 SQL` | 중요한 쿼리가 있는 경우 |
| `## 검색 처리 로직` | 알고리즘/정규식 기반 로직이 핵심인 경우 |
| `## 응답 코드` / `## 에러 코드` | 에러 처리가 있는 경우 |
| `## 알려진 제약 사항` | 미완성/한계가 있는 경우 |
| `## 히스토리` | 반복 업데이트되는 기능인 경우 |

### 변경이력형 (버그 수정, 특정 이슈 대응을 남길 때)

| 섹션 | 포함 조건 |
|------|-----------|
| `## 개요` | 항상 포함 |
| `## 무엇이 문제였나` | 항상 포함 |
| `## 어떻게 수정했나` | 항상 포함 |
| `## 관련 파일` | 항상 포함 |
| `## 주요 설계 결정` | 설계 배경이 있는 경우 |
| `## 동작 결과` | 실제 검증한 케이스가 있는 경우 |
| `## 알려진 제약 사항` | 미완성/한계가 있는 경우 |

## 검증 단계

문서를 다 쓴 뒤, 관련 소스 파일을 다시 읽어 엔드포인트/파라미터/응답 필드/SQL/분기 조건/파일 경로가 실제 구현과 일치하는지 하나씩 대조합니다. 프로젝트에 DB 조회 도구(MCP 등)가 있으면 테이블/컬럼/인덱스 존재 여부까지 확인하고, 없으면 코드/DDL 기준으로만 검증하며 확인 불가능한 내용은 단정하지 않습니다. 불일치를 찾으면 바로 문서를 고치고 아래처럼 결과를 보고합니다.

```
## 검증 결과
- 확인함: N건
- 수정함: N건
  - <무엇을 어떻게 고쳤는지>
- 확인 불가(DB 도구 없음 등): N건
```
