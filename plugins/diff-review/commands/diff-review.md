---

다음 단계를 순서대로 수행하세요.

## Phase 1: 변경사항 파악

`git diff HEAD`를 실행하세요.
변경된 파일이 없으면 사용자에게 알리고 종료하세요.

## Phase 2: 선택적 맥락 파악

diff만으로 판단하기 어려운 경우에만 해당 파일의 관련 라인 범위만 읽으세요.
- 파일 전체 읽기 금지, 필요한 라인만 offset/limit으로 읽을 것
- 연관 파일 탐색은 diff에서 명확히 필요한 경우에만 수행

## Phase 3: 리뷰 결과 출력

**이 단계에서는 파일을 수정하지 마세요.**

모든 심각도를 보고하되, Minor는 파일/라인 없이 한 줄로만 간단히 언급하세요.

각 이슈 형식:
```
### [Critical / Important] 제목
- 파일: `경로:라인`
- 내용: 문제 설명 (1~2줄)
- 제안: 개선 방법 (1~2줄)

### [Minor] 제목 — 한 줄 설명
```

이슈가 없으면 "이슈 없음"으로 간단히 종료하세요.

## Phase 4: 수정 여부 확인

리뷰 결과 출력 후 사용자에게 물어보세요:

```
수정할까요?
1. 전체 수정
2. Critical만 수정
3. 직접 선택
4. 수정하지 않음
```

사용자 응답에 따라 수정하거나 종료하세요.
