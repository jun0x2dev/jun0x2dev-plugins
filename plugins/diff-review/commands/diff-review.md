## Phase 2: 선택적 맥락 파악

- 연관 파일 탐색은 diff에서 명확히 필요한 경우에만 수행

## Phase 3: 리뷰 결과 출력

**이 단계에서는 파일을 수정하지 마세요.**

CLAUDE.md가 있으면 해당 규칙을 리뷰 기준에 포함하세요.

다음 관점에서 이슈를 찾으세요:
- 버그: 잘못된 로직, 예외 처리 누락, 엣지 케이스
- 보안: 인젝션, 노출된 민감정보, 인증/인가 문제
- 코드 품질: 불필요한 복잡도, 중복 코드, 읽기 어려운 구조
- 재사용성: 공통화 가능한 로직, 하드코딩된 값

각 이슈에 대해 0-100 사이의 신뢰도 점수를 매기세요:
- 0: 오탐. 가볍게 검토해도 근거가 없음
- 25: 불확실. 실제 이슈일 수도 있으나 검증 불가
- 50: 보통. 실제 이슈이나 자주 발생하지 않거나 중요도 낮음
- 75: 높음. 실제로 발생할 가능성이 높고 중요한 이슈
- 100: 확실. 반드시 발생하며 즉시 수정 필요

**신뢰도 50 미만 이슈는 제외하고 보고하세요.**

다음은 오탐 예시입니다 (보고하지 마세요):
- 기존에 이미 존재하던 이슈
- 린터/타입체커가 잡을 수 있는 이슈
- 시니어 엔지니어가 지적하지 않을 사소한 스타일 문제
- 의도적으로 변경된 것으로 보이는 동작 변경

각 이슈 형식:
```
### [Critical / Important / Minor] 제목
- 파일: `경로:라인`
- 내용: 문제 설명 (1~2줄)
- 제안: 개선 방법 (1~2줄)
```

이슈가 없으면 "이슈 없음"으로 간단히 종료하세요.
